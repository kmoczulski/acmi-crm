# User feedback, 2026-11-02 (brief for the follow-up model)

Seven items from the user's review. Each has the user's note, where the code lives as far as I could find it, and what I did not verify. Nothing here is changed yet.

## 1. Critical dates calendar should have its own tab; dashboard month change reloads the page

- **Note:** Critical dates calendar should have its own tab. On the dashboard, moving forward a month reloads the whole page.
- **Code:**
  - `crm/templates/crm/partials/critical_calendar.html` is the calendar. Prev/next are plain `<a href="{% qs_set crit=... %}#critical-dates">` links, so every month change is a full page navigation. That is the reload.
  - `crm/templates/crm/widgets/critical.html` includes that partial as a dashboard widget.
  - `crm/contracts/dates.py` → `month_calendar()` builds the month data.
- **Ask:** Move the calendar to its own page and tab (a new route plus nav entry in `base.html`). Month navigation should fetch or update only the calendar, not reload the page. Keep the dashboard widget or link to the new tab.

## 2. Calendar: weekly, daily and monthly views; person selection by checkboxes

- **Note:** The calendar view on its tab is monthly only. Add weekly and daily. Choosing whose calendar to view should use checkboxes, not only "view everyone".
- **Code:** Only `month_calendar()` in `crm/contracts/dates.py` and the partial above were found. I did not find a separate calendar tab or a per-person filter.
- **Ask:** Add week and day views to the same calendar. Add a checkbox list of people, default to all, filter by the checked set. Check first whether a meetings or gcal calendar view exists (`crm/gcal.py`, `crm/meetings.py`), since the note may mean that one.

## 3. CC / BCC address entry sometimes does not populate

- **Note:** Sometimes typing an email in CC or BCC shows nothing.
- **Code:**
  - `crm/static/crm/recipients.js`: the suggest box is shared by To, Cc and Bcc. It is attached once per input (`input.dataset.suggestOn`), and it fetches from `/inbox/suggest/`.
  - `crm/mail/search.py` → `recipients()` returns the suggestions.
  - `crm/templates/crm/compose.html` and `crm/static/crm/compose.js`.
- **Likely causes to check:** the CC/BCC inputs are shown or created after `recipients.js` runs, so they never get the `suggestOn` attach; or the suggest request is filtered; or the dropdown is hidden behind a field. I have not reproduced it.
- **Ask:** Reproduce in the browser on CC and BCC, check the console and the `/inbox/suggest/` response, then fix the attach timing or the request.

## 4. Suggest people to add, based on who the user is emailing

- **Note:** Add a "suggest person to add" feature based on who the user emails.
- **Code:** `crm/invites.py` and `crm/templates/crm/widgets/suggestions.html` and `partials/deal_suggestions.html` already show suggestion-style UI. Those may be for deals or meetings, not people. I did not read them in full.
- **Ask:** Look at the sent mail (`crm/mail/`) for recipients who have no `Person` record, rank by frequency and recency, and show them with a one-click "add person". Reuse the existing suggestion UI pattern if it fits.

## 5. Chat bar at the bottom gets in the way, especially on mobile

- **Note:** The chat bar at the bottom is sometimes in the way, especially on mobile.
- **Code:** I did not locate the bottom chat bar. A text search for "chat" in `crm/templates/crm/base.html` returned no matches, so the bar is probably in the mail dock (`crm/static/crm/dock.js`, `crm/templates/crm/mail_window.html`, `docs/MAIL_DOCK.md`) or in a partial. Verify before changing.
- **Ask:** Make it collapsible or dismissable, and on narrow screens keep it from covering content or the bottom nav. Check it at phone width.

## 6. Email search is weak; keyword search needs a separate function

- **Note:** Email search is still poor. To search by a keyword, the user has to use a different search function.
- **Code:** `crm/mail/search.py` has `expand()`, which adds company and person name matches. Its docstring says it is for names typed in the search box, and it explicitly skips queries with operators or quotes. `crm/mail/index.py` and `crm/mail/inbox_views.py` also touch search.
- **Ask:** Find the two search functions the user means (`grep -rn "def .*search"` under `crm/mail`). Merge them so one box searches keywords, names and addresses. Add a test in `crm/tests/test_mail.py`.

## 7. Phone web app seems to disconnect

- **Note:** The phone web app seems to disconnect.
- **Code:** `crm/static/crm/alerts.js` polls for notifications every 30 seconds and again on `visibilitychange`. I found no WebSocket or service worker. Phone browsers often pause or drop background requests, and the session cookie may expire.
- **Ask:** Get the exact symptom from the user first: does the page go to a login screen, show an offline error, or stop updating? Check session length in `config/settings.py` and any auth redirects. Do not guess the cause.

## 8. Contract viewer: group documents into sections by type

- **Note:** For the contract viewer, there should be sections for types of docs: a section for leases, PSA/LOI for land, PDAs, etc.
- **Code:**
  - `crm/models.py` `Contract.Kind` (around line 2322) has `loi`, `psa`, `option`, `lease`, `pda`, `jv`, `loan`, `easement`, `services`, `nda`, `other`.
  - `crm/contracts/views.py` `contract_list()` (line 38) passes `kind` as a single-value filter, and the list is a flat table in `crm/templates/crm/contract_list.html`. Each row shows `c.get_kind_display`.
  - The contract detail page is `crm/templates/crm/contract_detail.html`. I did not check whether it has its own type grouping.
- **Ask:** On the contract list, show one section per type group. Suggested groups: Land (PSA, LOI, option), Leases, PDAs / DMAs, and Other (JV, loan, easement, services, NDA, other). Keep the existing `kind` filter working. Confirm the grouping and order with the user before building.
