How it was run:

  tiles.
- **Page list:** built from `crm/urls.py` by reversing all 261 `crm:` routes and keeping every one whose GET returns
  a full HTML page (86), plus 8 query variants (table view, a county on the map, an open card and so on). That's 94

- **Every page at 1440×900 and 390×844** (188 loads) in Playwright Chromium, signed in as a Manager. Each load
  recorded status, console and page errors, failed same-origin requests, sideways overflow, tap targets under 24 px,
  unlabeled fields, a screenshot, and (at 1440) axe-core 4.10.2 for WCAG 2 A and AA.
- **Main actions** were scripted in the browser: create (blank name, double-click Save), edit then cancel then save,
  delete, sort, pager, saved view, Ctrl K, Tab order, Esc, dashboard and board moves by mouse and by keyboard with a
  reload, split view, and the phone + New menu, map and companies table.
- **Speed:** server time and query count per page with warm caches, using Django's test client on the same data.

### 1. Parcel card 500 when the status's author is gone

**Steps:** a team member marks a parcel Pursue / Watch / Pass. That user is later deleted (Django admin is mounted
at `/admin/`, `config/urls.py:9`). Open `/land/`, then click that parcel.
**Expected:** the card, with the status and no name. **Actual:** `GET /land/parcel/1/` is a 500. With
`DJANGO_DEBUG=true` the map's side panel shows Django's debug page (screenshot). With DEBUG off it would be
Django's plain "Server Error (500)", since there's no `500.html` (not checked in the browser).

```
crm/models.py:1959:    status_by = models.ForeignKey(User, null=True, blank=True, on_delete=models.SET_NULL, related_name="+")
crm/templates/crm/partials/land_card.html:26:  {% if p.status %}<div class="muted lc-small">{{ p.get_status_display }} · {{ p.status_by.get_full_name|default:p.status_by.username|default:"" }} ...
```
A filter *argument* that fails to resolve isn't silenced in Django templates, so `default:p.status_by.username`
raises when `status_by` is `None`:
```
django.template.base.VariableDoesNotExist: Failed lookup for key [username] in None
```
`parcel_check` and `parcel_notes` return the same card (`_card`), so they fail too: a POST to
`/land/parcel/1/check/` or `/notes/` was a 500 for both team roles in the access crawl. The notes are saved
before the card renders, so the person sees an error even though the save worked. **Fix:** `{% if p.status_by %}…{% endif %}` around the name,
or `p.status_by|username`.

### 2. Inbox actions 500 when Google refuses the token

**Steps:** a person's Google token is revoked or can't refresh. Open `/inbox/`, then a message.
**Expected:** the same "Google didn't accept the hub's Gmail permission. Turn on Mail again…" message the inbox
list shows. **Actual:** a server error in the reading pane, and on the other actions. Reproduced with the token
refresh refused in-process, with no network:
```
GET  /inbox/                      200
GET  /inbox/m/m1/body/            500
GET  /inbox/m/m1/part/1/          500
GET  /inbox/t/3e8/files.zip       500
POST /inbox/t/3e8/summary/        500
POST /inbox/note/                 500
```
`inbox` and `_pane` catch `(MailboxError, requests.RequestException)` (`inbox_views.py:144`, `:176`).
`message_body`, `message_part`, `thread_files_zip`, `thread_summary` and `comment_add` catch only `NotFound`, e.g.:
```
443:     try:
444:         msg = mail_render.get_message(mailbox, client, message_id)
445:     except NotFound:
446:         raise Http404()
```
and `GmailClient._access` turns a refused refresh into `MailboxError` (`crm/mail/gmail_api.py:118-121`). The same
500 happens whenever Gmail is busy (`gmail_api.py:160`) or the network drops (`requests.RequestException`). **Fix:**
catch both in those five views and return the reconnect message, as a small HTML page in the frame and as JSON for
Summarize.

### 4. Pipeline table: wrong count and lost deals first

**Steps:** `/opportunities/`, then Table. **Expected:** the 88 open deals the header counts, in the board's order,
with closed ones behind "Show" as on the board. **Actual:** 158 rows (On hold 29, Signed 25, Qualified 21,
LOI/PDA signed 18, Lease negotiation 17, Prospect 17, Cold/lost 16, LOI/PDA negotiation 15), and the first 16 are
Cold / lost.
```
crm/views.py:671:    deals.sort(key=lambda o: (-STAGE_ORDER[o.stage], -(o.value or 0), o.name))
crm/models.py:91:STAGE_ORDER = Lookup("OpportunityStage", {value: i for i, value in enumerate(OpportunityStage.values)})
```
`STAGE_ORDER` numbers the stages in model order, Prospect 0 … Lost 7, so the descending sort puts Lost and On hold
first. The board collapses those two columns unless `closed=1` (`views.py:677`). The table loop
(`opportunity_board.html:32` `{% for o in deals %}`) shows everything. **Fix:** in the table, hide on hold and lost
unless `closed=1`, add a "Show closed" link, and sort open stages first (or by the board's column order).
