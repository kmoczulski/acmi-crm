# Code review and audit: the week of Oct 21 to Oct 26, 2026

Reviewed on branch `claude/beautiful-albattani-6xp3qi` from `main` at `747a373`, against the last commit before
Oct 21 (`4af11b8`, Oct 19). The week added 293 files and about 27,600 lines across 77 commits: the UX overhaul and
dashboard, boards, the directory and Claude's domain sorting, the capital tracker, contract redlines and the closing
timeline, the data room and Drive panels, browser notifications, and the eight steps of Mail in the hub. The baseline
suite (710 tests) was green before any change here; it is green after, with five tests added (715).

## What was fixed on this branch

Each fix has a test. Migration `0068_data_room_login_attempts` adds one table; back the real database up before it.

1. **Data room sign-in lockout held in the database, and keyed on the real client.** `crm/dataroom/logic.py` counted
   wrong passwords in Django's default cache, which is per process and in memory: with two gunicorn workers (and more
   than one Cloud Run instance) each worker had its own count, and a restart cleared it. Worse, the address key was
   `REMOTE_ADDR`, which behind Cloud Run's front end is the proxy, the same for everyone, so five wrong passwords from
   anyone would have locked every partner out for 15 minutes. Strikes now live in `DataRoomLoginAttempt`
   (`crm/models.py`), and `_ip()` in `crm/dataroom/views.py` reads the last `X-Forwarded-For` entry, the one the proxy
   appends, whenever `SECURE_PROXY_SSL_HEADER` is set (production). On the laptop nothing changes. If a load balancer
   is ever put in front of Cloud Run, revisit `_ip()`: it would then append its own address after the client's.
2. **Board card attachments can't run as part of the hub.** `attachment_file` in `crm/boards/views.py` served every
   upload inline with the content type guessed from the *name the person typed*, so a teammate could upload `x.html`
   (or an SVG with a script) and it would render on the hub's origin with everyone's cookies. It now follows the
   stored file's extension and the same inline allow-list as every other file view (PDF and pictures open in the
   page; everything else downloads). Insider-only, but the same pattern the other views already avoided.
3. **A line break in an address or threading header is a message, not a 500.** `compose.build` in
   `crm/mail/compose.py` set `To`, `In-Reply-To` and `References` straight from the form; Python's email library
   refuses header values with a line break (which also means nobody could inject a header), but it did so with a
   `ValueError` the page didn't catch. It's now a `ComposeError` shown on the form.
4. **Worker threads close their database connections.** The Gmail client fans out over `ThreadPoolExecutor`
   (`gmail_api.read_changes`, `index.refresh`, `actions.apply`, the Files view). A worker that has to refresh the
   access token saves it, and Django never closes a worker thread's connection on its own, so a long-running server
   could collect idle Postgres connections. `gmail_api.parallel_map` now runs every pool and closes the thread's
   connections after each call.
5. **Capital partners' accounts are never offered as "ACMI" teammates** in the To / Cc / Bcc suggestions
   (`crm/mail/search.py` used every active user; it uses `team_users()` now, like everything else).
6. **Cloud Build was missing the new secrets.** `cloudbuild.yaml` never passed `ACMI_TOKEN_KEY`, so on the first deploy
   the web service and the sync job couldn't have read any stored Google token (no Mail, no calendar sync) and
   `tokens.configured()` would have kept Mail from being turned on. The send job had no Google client at all, so with
   Kellen's app password gone from `.env` an outreach batch would have failed to send. All three jobs and the service
   now get `ACMI_TOKEN_KEY`; the send job gets the Google client id and secret; the sync job gets the Anthropic key
   (it runs `sort_domains`) and the VAPID pair (it runs `notify_sweep`); the service gets the VAPID pair. The header
   lists the three new Secret Manager secrets to create: `acmi-token-key`, `acmi-vapid-public-key`,
   `acmi-vapid-private-key`. Nothing is deployed yet, so this is a pre-deploy fix.
7. **Attaching more than one file** (Kellen, same day: "I can only attach one document in email?"). The compose page
   and the inline reply used a bare `<input type=file multiple>`, so picking a file after the first replaced it.
   `compose.js` now adds every pick to a list under the Attach button, each with a ✕, shows the total against
   Gmail's 25 MB, and the form sends them all; the inline box empties its list when you open another reply.
8. **Smaller:** `cryptography` and `google-auth` are pinned in `requirements.txt` (both imported directly, both were
   only transitive); the Fernet for token encryption is built once per key set instead of on every token load
   (`crm/tokens.py`); `.env.example` lists every new variable (Google client, token key, VAPID, Drive, the mail
   switches); the README layout table covers the new modules.

## Second pass, same day: every section of the hub, on a scratch copy

Kellen: "continue to audit everything possible, go through each section of the web app and double check
everything", and "the lack of commas for amounts: in the QD arc when I put in 10,000 it shows 10000".

How it was done, so it can be repeated: a scratch SQLite database (never the real one) seeded with made-up rows in
every module (companies, people, deals, activity, meetings, tasks, lists, boards, capital sources and term sheets,
contracts with drafts and dates, entitlements, build budget, land parcels with a QD plan, sites, a client search,
diligence, a data room, the mail index, news, outreach). Then every URL pattern in `crm/urls.py` (244 of them, plus
about 100 query-string variants) fetched three ways: as a Manager, as a plain team member, and signed out, with the
SQL counted per page; and the main pages opened in Chromium for console errors and the number formatting exercised
by typing into the fields. Scripts were throwaway; nothing of them is in the repo.

9. **Amounts take and show thousands separators everywhere.** Number fields on every `StyledForm` (and the plain
   model forms, via `CommaNumbersMixin` in `crm/forms.py`) render as text fields marked `data-commas`; `nav.js`
   shows them with separators as you leave the field and the form posts plain digits, while the server strips
   commas and dollar signs anyway (`comma_numbers`). The QD planner and the site plan use the same marker and
   `acmiNum.parse`, so "10,000" stays "10,000" and still computes. Hand-written inputs (build budget, draws, change
   orders, bids, contract amounts, diligence budgets, site-search acreage, ROM amounts, capital quick-add, fit
   square footage) were marked the same way, and a few displayed figures gained separators (acres on site tiles and
   campus sections, square feet on the site page, rent per square foot). Tests: `crm/tests/test_numbers.py`.
10. **Five pages crashed when a user was missing.** A Django template argument like
    `|default:p.status_by.username` raises when `status_by` is None (the fallback never runs), so: the parcel card
    for a parcel whose status came from an import, the shared mailbox access log for a deleted teammate (the very
    case its "(deleted)" fallback was written for), a site card comment whose author is gone, Mail settings when
    the person who connected a shared mailbox has left, and the outreach queue preview for a person with no
    company. Each now uses the `username` filter or `firstof`. One test per page.
11. **The Tasks page came back in database order.** Its query carries a comment count (a GROUP BY), and Django
    drops `Meta.ordering` on grouped queries, so Postgres returned the rows however it liked. The ordering is
    spelled out (`TASK_ORDER` in `crm/views.py`) and the same helper now feeds the task lists on company, person and
    deal pages, which also gives those rows their comment counts in one query. Test.
12. **Gmail failing after the inbox loaded was a 500.** The reading frame, an attachment, Download all, Summarize,
    opening a reply or forward and saving a draft each call Gmail on their own; a revoked token or a busy Gmail put
    Django's error page inside the reading pane. They now say what happened: the frame shows the words (502), the
    JSON endpoints answer 503 with the message, the page actions redirect with it. Test.
13. **Fewer queries per page.** The campus summary asked five questions per deal (last email in and out, last and
    next meeting, contracts); it now asks four for the whole campus (`_touches` in `crm/campus.py`) and prefetches
    contracts with their dates. The dashboard's "replies waiting on us" asked once per reply whether it had been
    answered; one query now. Company pages load meetings with their transcript flag and recent activity with its
    team members. On the scratch data: home 58 to 44 queries, company page 54 to 42, deal page 40 to 36, campus
    122 to 107 (what remains there is per site and per project inside the build, capital and entitlement logic,
    about ten each, a handful per campus).
14. **Map overlays only ask the servers that cover the view.** `regional()` in `land_layers.js` keeps a layer on the
    map only while the view touches its area, so the Texas parcel export, Texas city limits, Charles County parcels,
    zoning and towns, and the Huntsville parcels, zoning and Alabama places no longer fire on every move over
    somewhere else. The Huntsville parcel layer now asks for the picture itself (`f: 'image'`): the city's server
    sends no CORS header, so the layer had never drawn in any browser (the console showed the refusal on every
    move); its zoning layer uses JSONP for the same reason. Checked in Chromium over a Maryland parcel (only the
    Charles County services called) and a Texas one (only Texas).
15. **Smaller:** the contract comment form's `next` can't send someone to another host (`//evil` passed the
    "starts with /" check); a bad `zoom` on `parcels.json` or a bad `index` on make-a-task-from-a-meeting falls
    back instead of a 500.

**Checked in the second pass and sound.** Signed out, GET and POST on every URL reach only the guest site-search
pages, the room sign-in and the service worker. A plain team member (not a Manager) is sent home from settings,
dropdowns, data rooms, shared mailbox grants and the access log, outreach settings and templates, contract delete and
move-to-directory. Every file endpoint shows only PDFs and pictures inline (`INLINE_TYPES` in eight modules; data
room files always download). Every `mark_safe` and `|safe` is fed by an escaping builder (`contracts/ai.py`,
`contracts/text.py`, `meetings.render_markdown`) or `sanitize_html` (signatures, drafts); no `autoescape off`. The
scheduler endpoint is the only CSRF-exempt view and compares its secret in constant time. Redirect targets are
checked for a local path; JSON bodies are parsed under `try`; no raw SQL; no tokens in logs or in the admin. No
template renders a raw `{{ }}`; no page raised on the crawl after the fixes above.

## What was checked and is sound

- **Mail HTML in the reading pane.** Bodies pass the allow-list sanitizer (`crm/news/drafts.py`), are served on their
  own URL inside an iframe with `sandbox` (no scripts) and a CSP of `default-src 'none'`, remote images held back
  until "Show images" (so tracking pixels don't fire), inline `cid:` images proxied through the hub, attachments
  always downloaded as `application/octet-stream` except PNG/JPEG/GIF/WebP shown inline under their own
  `sandbox` CSP. Links open in a new tab outside the sandbox. The frame view is `xframe_options_sameorigin` and
  sets its own CSP, so the site-wide `frame-ancestors 'none'` doesn't block it. This is the right design; keep the
  sanitizer and the frame CSP together if either changes (the `style` attribute is allowed through a blacklist, and
  it's the CSP that makes that safe).
- **The hub's own pages** escape everything that comes from email before it reaches `innerHTML` (attachment names in
  the inline reply box, sender names and search hits in `recipients.js`, `nav.js`, `board.js`, the inbox's summary
  and File-to boxes). The only `|safe` uses in templates are sanitized signatures, server JSON and server CSS.
- **Token encryption** (`crm/tokens.py`): encrypt on `pre_save`, decrypt on `post_init`, plain again in memory after
  save, `MultiFernet` for key rotation, `.update()` paths covered by `encrypt_all`. Shared mailbox tokens use the same
  path. Mail can't be turned on without a key, so a Gmail token is never stored plain.
- **Data room.** Everything a partner sees is built from allow-lists (`ROOM_COLUMNS`, `card()`), never from an
  internal template with parts hidden. `PartnerOnlyMiddleware` sends a partner anywhere else back to `/room/`;
  `team_users()` excludes them from assignees, mentions, the mail sync's teammate list, calendar sync and
  suggestions; a partner moved into the Partners group or deactivated loses Mail (signals). Invite links are hashed,
  single use, 14 days; passwords are 12+ characters with Django's validators. Switching a member or a room off ends
  sessions at once (inactive users fail `get_user`). Drive files are streamed through the hub as downloads, Drive
  errors never reach the partner.
- **Redirects and CSRF.** Every `next` / `back` is checked with `url_has_allowed_host_and_scheme` or a leading `/`
  without `//`; `notification_open` allows only hub paths and `https://mail.google.com/`; all state changes are
  POSTs with the CSRF token; the cron endpoint refuses when `ACMI_CRON_SECRET` is unset.
- **File views** (`document_file`, `contract_file`, `term_sheet_file`, `approval_file`, `bid_file`,
  `diligence_file`, the data room) take the stored file's extension and an inline allow-list. Board attachments
  were the one exception (fixed above).
- **Migrations 0051 to 0067** run in order on a fresh database; the four data migrations (critical flag, directory
  rename and team links, duplicate alerts, token encryption) are reversible or no-ops backwards.
  `makemigrations --check` and `check --deploy` pass (one optional warning: HSTS preload).
- **Gmail API client.** Retries only on rate limits and transient errors, never after a send (an `UnconfirmedSend`
  stops a batch so nobody gets an email twice); 401 refreshes the token once; the shared-mailbox OAuth flow checks
  `state` with `compare_digest`, the `email_verified` claim and that the address is the one asked for.
- **Boards.** Record boards move cards from a `post_save` signal and set a context variable so a drop doesn't move the
  card twice; feed lists are read-only; deletes and archive need a Manager.
- **The Claude features** (contract intake, timeline, redline notes, term sheets, domain sorting, thread summary) use
  structured output with closed schemas and anchor quotes in code, so a model answer can't put arbitrary fields or
  HTML on a page; prompts say the email text is data, not instructions.

## Flagged, not changed (your call, or a bigger change)

- **Claude files directory firms automatically** from the mail review queue (`crm/directory/sort.py`): a "high"
  confidence directory verdict creates a `Firm` with contacts read from signatures, no click. The evidence is
  untrusted email, so this is a prompt-injection surface in the strict sense. The mitigations are good (closed
  schema, contacts only kept at the domain's own addresses, never a Company, Managers get a bell note, Undo puts the
  mail back). If you'd rather every filing be a click, change `auto_sort` to record the suggestion and skip
  `file()`; everything else already works that way.
- **Browser push is sent inside the request.** `push.deliver` runs in `transaction.on_commit`, synchronously, with a
  5 s timeout per browser. A comment that mentions someone with three devices can add up to 15 s to that request
  when a push service is slow. Fine for a small team; move it to a thread or the sync if it's ever felt.
- **The cache is per process.** No `CACHES` setting, so Django's in-memory cache (300 entries, culled by a third
  when full) holds Gmail thread payloads, Drive listings, the label-refresh flag and thread summaries, separately
  in each gunicorn worker. On the laptop that's fine; on Cloud Run threads get refetched more often than they
  need to be. Don't move mail bodies into a database cache (they'd sit unencrypted in a table); a bigger
  `MAX_ENTRIES` is the only cheap lever, and memory is the trade.
- **Partners can also sign in through `/accounts/login/`** (the `PartnerBackend` is in `AUTHENTICATION_BACKENDS`,
  so Django's `authenticate()` reaches it from any login form). They land in the room all the same, allauth
  throttles that form (10 a minute per address, 5 per 5 minutes per account), but the room's own sign-in log and
  lockout aren't involved. Harmless today; restrict the backend to `/room/` requests if you want one door.
- **Partner sessions last two weeks** (Django's default `SESSION_COOKIE_AGE`). Consider a shorter life for the
  room, e.g. by setting `request.session.set_expiry()` in `room_login`.
- **Inline scripts.** The site CSP allows `'unsafe-inline'` scripts because the templates use them. Moving to nonces
  is the long-term fix; it's a template-wide change.
- **A signed-in teammate who clicks a partner's invite link is logged out** (`room_invite`), by design, with no
  message. A Manager testing a link they just made will hit this.
- **Download all** builds the zip in memory, up to 100 MB (`thread_files_zip`). OK for a team of six.
- **Query volume in the inbox:** `index.chips()` loads every company's and firm's domains on each inbox render
  (about 1,800 rows, fast today); `crm_labels.sync_threads` runs two queries per thread, so the one-off 90-day
  backfill is a few thousand queries; the data room's "newer version" check lists every mapped project folder per
  room-wide Drive file (cached five minutes). None is a problem at today's size.
- **Deploy config still to add when the time comes:** `ACMI_DRIVE_ADC=true` and `ACMI_DRIVE_TENANCY_FOLDER` on the
  service once the runtime service account is a Viewer on the shared drive; `acmi-imap-password-kellen` can be
  dropped once nobody syncs over IMAP.
